# 면접 준비·지원 현황·일정

## 면접은 제출한 사실에서 시작한다

사용자가 실제 제출본을 제공했다면 초안과 구별해서 읽는다. 접수 증거가 없으면 “제출됐을 것으로 추정”하지 않는다. 공고와 회사 조사도 최신 공식 자료로 재확인한다.

1. 현재 JD의 업무 과제·핵심 역량과 지원서의 대표 주장을 나열한다.
2. 주장마다 `근거 파일/페이지 → 예상 질문 → 지원자 직접 행동 → 결과 범위 → 한계`를 연결한다.
3. 모르는 내용과 준비가 필요한 기술/산업 개념을 분리한다. 외우기 위한 가짜 답을 만들지 않는다.
4. 짧은 자기소개는 핵심 역량과 대표 경험 중심으로 작성한다. 말하기 길이는 실제 읽은 시간으로 확인하며 글자 수로 발화 시간을 단정하지 않는다.

## 질문 묶음

- **직무:** 해당 업무의 성공 기준, 우선순위, 고객/동료와의 인터페이스, 판단에 필요한 정보.
- **경험:** 왜 그 대안을 골랐는가, 정확히 어떤 산출물을 직접 만들었는가, 다른 구성원과의 책임 경계는 무엇인가.
- **성과:** 기간·분모·대상은 무엇인가, 결과를 어떻게 확인했는가, 팀·회사 성과 중 본인 기여는 어디까지인가.
- **실패/갈등:** 언제 기존 판단이 틀렸음을 알았는가, 어떤 행동을 바꿨는가, 해결되지 않은 한계는 무엇인가.
- **지원동기:** 다른 회사가 아니라 해당 법인/직무를 고른 근거는 무엇인가. 확인하지 못한 내부 상황은 가설로 말하는가.
- **역질문:** 공개 자료에 없는 직무의 기대 성과·협업·업무 범위 확인. 민감한 내부 자료 공개를 요구하지 않는다.

질문은 실제 기출과 연습용 예측을 구분한다. “이 회사가 반드시 묻는다”는 표현은 검증된 출처 없이 쓰지 않는다. 케이스·과제의 비공개 시험 내용을 수집하거나 대리 응시하지 않는다. 인성검사·행동검사는 지원자의 실제 선택이며 회사에 맞춰 최적화하지 않는다.

## 모의 면접 운영

한 질문씩 묻고 답을 기다린다. 답변을 대신 작성해 지원자 경험처럼 꾸미지 않는다. 피드백은 `정확성 / 본인 판단 / 개인 기여 / 결과 범위 / 명료성`으로 나누고 실제 발언을 근거로 준다. 개선 답변에서도 사실·도구명·수치를 보존한다. 연습용 예상 답변과 실제 확인된 진술을 분리한다.

## 상태는 증거로만 전환한다

아래는 업무 단계 설명이며 CLI의 허용 상태 이름은 `track --help`로 확인한다.

| 업무 단계 | 필요한 증거 |
|---|---|
| 공고 발견 | 실제 URL·제목·조회 시각; 상세 미확인 여부 |
| 자격 확인 | 현재 공식 요건과 지원자 증빙의 대조 |
| 문항 확보 | 현재 양식 문항 원문·제한·확인 시각 |
| 초안/검토 | 버전 경로·근거 장부·계산 결과·검토 지적 |
| 온라인 저장 | 사용자가 확인한 저장 본문·상태·시각. 로컬 파일 생성으로 대체하지 않는다. |
| 제출 확인 | 접수번호/완료 화면 등 직접 증거와 확인 시각. 초안·업로드와 구별한다. |
| 면접/결과 | 사용자에게 온 공식 안내의 단계·일정·응답 기한 |

```text
python3 -m korean_job_search track --job JOB_ID --status STATUS --confirm
python3 -m korean_job_search report --jobs workspace/jobs.json --out workspace/reports/jobs.html
```

`JOB_ID`는 실제 공고 ID, `STATUS`는 지원되는 상태 중 확인된 값이다. 이 명령은 **로컬 기록**만 바꾼다. `--confirm`은 채용 사이트 제출 승인이 아니며, 명령 성공은 접수 완료의 증거가 아니다. 사용자 확인이나 접수 증거 없이 제출 상태를 기록하지 않는다.

보고서를 실제로 열어 대상 수·상태·오류·마감·링크를 확인한다. HTML에 민감정보가 있으면 `workspace/` 밖으로 복사하거나 외부 호스팅하지 않는다. 링크 열기만으로 제출·취소가 일어나지 않는 공개 상세 URL을 사용한다.

## 일정과 충돌

마감·면접·시험·입사일을 별개로 기록한다. 원문 시각과 KST (`UTC+09:00`), 출처, 확인 시각을 보존한다. 일정이 겹치면 이동·준비 시간과 중복 지원 규칙을 포함해 사용자에게 선택지를 보여주고 대신 취소하지 않는다.

마감 연장·회차 변경은 공식 정정 공고로 확인한다. 날짜만 알면 시각은 미확인으로 남긴다. `report`는 달력·알림·자동 감시 기능이 아니다. 별도 승인 없이 cron, 전역 훅, 캘린더 공유, 자동 지원을 설치하지 않는다. 알림을 따로 요청받았다면 실제 등록 결과와 다음 실행 시각을 읽어 검증한 경우에만 등록됐다고 말한다.
