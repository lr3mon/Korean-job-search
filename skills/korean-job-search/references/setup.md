# 설정·근거 장부·경험 은행

## 비공개 작업 공간부터 만든다

1. 저장소 루트에서 `python3 -m korean_job_search doctor`와 `python3 -m korean_job_search init`을 실행한다. 출력 경로·경고를 읽는다. 기존 파일을 덮어쓰지 않는다.
2. `workspace/`가 `.gitignore`로 제외되는지 확인한다. 검증 가능한 터미널이 있다면 `git check-ignore workspace/profile.json`으로 확인한다. Git이 없다면 제외 규칙을 직접 읽고 공개 업로드를 하지 않는다.
3. 사용자에게 지정받은 문서만 읽는다. 프로필·외부 저장소·다른 에이전트 메모리 자동 탐색은 금지한다. 인증정보나 주민등록번호는 이력 근거로도 수집하지 않는다.
4. 자료의 파일 경로·문서 제목·페이지/행·확인 시각을 기록한다. 개인 자료를 공용 검색 질의에 넣지 않는다. 스캔/이미지 자료는 실제 읽을 수 있는 OCR·시각 도구가 있을 때만 판독하고 불확실한 글자를 확인 요청으로 남긴다.

## 최소 질문

이미 제공된 자료로 답할 수 없는 것만 묻는다.

- 원하는 직무·신입/경력 구분·근무지·고용형태·입사 가능일.
- 반드시 지켜야 할 배제 조건과 지원 회사 범위.
- 현재 지원할 공식 JD URL, 실제 양식 접근 가능 여부.
- 활용해도 되는 이력서·프로젝트·성과 증빙, 비공개/익명화가 필요한 부분.
- 이번 범위: 탐색, 초안, 검토, 면접, 로컬 추적 중 어디까지인지.

일단 확인된 자료로 진행하되 빠진 졸업 여부·국적·언어 점수·군 경력·건강·가족 배경을 추정하지 않는다. 민감정보는 직무 검토에 필요하지 않으면 요청하지 않는다.

## 프로필은 조건과 검증된 경험만 넣는다

`workspace/profile.json`의 `target_roles`, `keywords`, `preferred_locations`, `excluded_keywords`, `experience_level`, `stories`를 실제 요구에 맞춘다. `display_name`은 선택 사항이다. 목표 연봉이나 법적 지원 자격처럼 CLI에 별도 구조가 없는 값은 비공개 근거 메모로 남기며 자동 점수에 반영된다고 주장하지 않는다.

`stories`에는 `id`, `title`, `period`, `role`, `actions`, `results`, `evidence`를 기록한다. 긴 판단·불확실성 기록은 [경험 장부](../templates/story-evidence.md)를 비공개 작업 공간으로 복사해 작성한다. 템플릿 원본에 실제 경력을 넣지 않는다.

## 근거 우선순위

1. 직접 증빙: 계약·확인서·본인이 만든 산출물·접수 기록·정확한 원본 문서.
2. 사용자가 현재 확인한 진술: “지원자 확인”으로 표시한다. 독립 검증으로 격상하지 않는다.
3. 이전 이력서/지원서: 강한 발견 단서지만 오류를 재활용하지 않게 직접 증빙과 대조한다.
4. 기억·요약·모델 추정: 사실 근거로 쓰지 않는다.

각 주장에 `출처`, `누가 확인했는지`, `확인 시점`, `범위`, `불확실성`을 붙인다. 서로 다른 기간·수치가 있으면 충돌 장부로 분리한다. 이름·수치·기간·모델 버전을 멋대로 정규화하거나 최신 이름으로 교체하지 않는다.

## 경험 인터뷰 순서

경험별로 실제 있었던 일에 한해 다음을 묻고 요약을 사용자에게 확인받는다.

1. 어떤 문제가 누구에게 어떤 비용을 만들었는가?
2. 본인이 맡은 범위와 다른 사람의 범위는 무엇이었는가?
3. 어떤 신호를 보고 무엇을 비교했으며 왜 그 방법을 골랐는가?
4. 누구와 어떤 행동을 했고 어떤 산출물을 남겼는가?
5. 본인이 확인할 수 있는 결과는 무엇이며 팀·회사 결과와 어떻게 다른가?
6. 이후 실제로 바꾼 의사결정 기준이나 절차가 있는가?

숫자가 없으면 산출물·승인·배포·채택·관찰된 변화로 구체화한다. 그 사실조차 없으면 확인 필요로 남긴다. 단순한 전후 수치를 통제 실험에 의한 인과나 개인 단독 성과로 쓰지 않는다.

## 완료 기준

프로필 조건과 경험의 출처가 연결되고 누락·충돌이 보이며, 사용자가 공개하지 않기로 한 내용은 제외되어야 한다. 설치 성공이나 빈 템플릿 생성은 경험 정리 완료가 아니다.
