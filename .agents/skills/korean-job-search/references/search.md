# 공식 우선 탐색과 JD 조사

## 검색 범위부터 고정한다

대상 회사·법인·직무·지역·경력 수준·채용 회차를 기록한다. 그룹명과 실제 고용 법인을 혼동하지 않는다. 사용자가 한 회사를 지정했다면 편한 계열사로 바꾸지 않는다. 여러 회사가 대상이면 모든 요청 항목을 목록으로 만들고 중복 제거·완료 수를 도구로 집계한다.

`python3 -m korean_job_search sources`로 실제 등록 소스를 읽는다. 주요 기업 디렉터리는 채용 창구 목록이며 매출 순위나 개별 파서 지원 목록이 아니다. 그룹 채용 사이트를 여러 법인이 공유할 수 있다.

```text
python3 -m korean_job_search discover --query "직무 검색어" --company "정확한 회사명"
python3 -m korean_job_search discover --query "직무 검색어" --all-companies
```

`discover`가 준 계획과 검색어를 **실제 호스트 웹 검색 도구**로 실행한다. 도구가 없으면 계획을 `handoff`로 전달한다. 검색 결과 제목·스니펫은 발견 단서이지 공고 본문·마감의 증거가 아니다.

## 출처를 이 순서로 확인한다

1. 회사 공식 홈페이지가 연결한 채용 사이트의 해당 공고, 첨부 공고문, 정정 공고, 현재 지원 양식.
2. 회사 공식 IR·사업/제품·기술 문서. 회사 이해에만 쓰고 비공개 내부 문제를 추정하지 않는다.
3. 공공기관이면 기관 채용 원문·첨부와 JOB-ALIO, 고용 관련 공식 공공 안내. 공식 점수표를 읽는다.
4. 사람인(Saramin), 잡코리아(JobKorea), 원티드(Wanted)는 발견과 교차 확인에 사용한다. 최신 공식 원문을 찾고, 없으면 플랫폼 출처임을 밝힌다.
5. 뉴스·취업 커뮤니티·이전 합격 자소서는 보조 자료다. 합격 사례의 경험·문장·수치를 복사하지 않고, 이전 문항은 현재 문항으로 사용하지 않는다.

공식 홈페이지와 채용 도메인의 관계도 확인한다. 로고·도메인 철자·검색 순위만으로 공식이라고 단정하지 않는다. 별도 ATS는 공식 회사 페이지의 링크로 관계를 입증한다.

## 수집과 상태 해석

```text
python3 -m korean_job_search collect --source SOURCE_ID --query "직무 검색어" --limit 20 --out workspace/jobs.json
python3 -m korean_job_search ingest --url "https://공식-도메인/실제-공고"
python3 -m korean_job_search ingest --file workspace/sources/posting.txt --source-url "https://공식-도메인/실제-공고"
```

`SOURCE_ID`와 URL은 확인한 실제 값으로 바꾼다. 기존 공고 파일이 있으면 변경 전 보존하고 병합·중복 제거를 검증한다. 수동 원문을 `live_html`처럼 위장하지 않는다. 출력 JSON·실제 저장 경로를 확인한 뒤 그 파일을 `rank --jobs`로 전달한다.

| 수집 상태 | 해야 할 일 |
|---|---|
| `ok` | 실제 공고 상세 본문·링크·원문 시각이 있는지 확인한다. 성공 상태도 완전성 보증은 아니다. |
| `partial` | 일부 페이지·목록만 확인됐다는 경계를 기록한다. 남은 페이지·본문을 인계한다. |
| `empty` | 검색 범위·필터·조회 시각을 적는다. 전체 회사의 채용 없음으로 확대하지 않는다. |
| `needs_browser` | 먼저 원시 HTML의 공고 링크를 확인한다. 파서 미지원과 실제 JS 필요를 구분하고 [Scrapling 보조 수집](scrapling.md)을 적용한다. 도구가 없으면 인계한다. |
| `needs_credentials` | 로그인 이후 정보가 필요함을 알리고 안전한 사용자 인증으로 인계한다. |
| `blocked`, `robots_denied` | 명시적 Disallow / robots 정책 조회 실패 / HTTP 차단을 진단에서 구분한다. 자동 수집은 중단하고 공식 원문·허용된 사용자 제공 자료로 전환한다. 실패를 공고 없음으로 쓰거나 자동 우회하지 않는다. |
| `unsupported`, `error` | 실패 이유와 시도한 URL을 보존한다. 다른 허용된 공식 표면이나 사용자 제공 원문으로 전환한다. |

카드 재수집 뒤에 이전 JD가 유지되었으면 `warnings`와 `observations`를 읽는다. 본문·마감·문항을 서로 다른 시점에서 임의로 섞거나 보존된 옛 본문을 새로 확인한 것으로 표현하지 않는다. 최신 카드와 이전 상세가 충돌하면 현재 공식 상세/정정 공고를 다시 읽고, 확인 전에는 낙관적 마감을 택하지 않는다. 명시적인 `deadline: null`은 미확인 판단이므로 원문을 다시 추정해 정확한 KST 시각으로 바꾸지 않는다.

HTTP 200, 메뉴, 빈 JavaScript 셸, 목록 카드만으로 전체 JD를 확보했다고 말하지 않는다. 이미지 공고는 실제 시각 도구로 읽고, 없으면 원본 확인을 사용자에게 요청한다. 인증 필요 문항을 찾으려고 비슷한 검색을 무한 반복하지 않는다.

수집 결과의 상태와 에이전트 작업 상태를 분리한다. 아래는 CLI 반환 스키마가 아닌 **작업 인계 메모 형식**이다.

```text
work_status: handoff
acquisition_status: 실제 반환값 또는 not_attempted
source_url: 실제 시도한 원문 URL
attempted: 실행한 도구와 확인 범위
missing: 공고 본문 / 현재 문항 / 마감 정밀도 등
reason: 접근 제한 또는 없는 도구
next_action: 필요한 사용자 자료 또는 허용된 도구
```

## 자격을 적합도보다 먼저 검증한다

공고 원문을 요구사항 표로 분해한다: `정확한 인용 | 필수/우대 | 지원자 증거 | 충족/불충족/미확인 | 출처`.

- 졸업 시점·학위·전공·경력 기간·근무 가능 지역·입사일을 각각 확인한다. 우대를 필수로, 관련 전공 예시를 폐쇄적 자격 목록으로 바꾸지 않는다.
- 어학은 시험명·점수 체계·유효기간을 그대로 비교한다. 서로 다른 시험의 같은 등급 이름을 서로 대체하지 않는다.
- 그룹/법인/직무 간 중복 지원 규칙과 전형 충돌을 순위 제시 전에 확인한다.
- 공공기관은 **지원 자격 / 서류 점수 경쟁력 / 필기(NCS·전공) 준비 가능성 / 경험 적합성**을 따로 평가한다. 점수와 배점은 원문·증빙을 기반으로 계산한다.
- 사용자에게 불리하거나 민감한 신상정보를 새로 추정하지 않는다. 명시 자격을 확인하는 데 필요한 최소 정보만 요청한다.

```text
python3 -m korean_job_search rank --jobs workspace/jobs.json --profile workspace/profile.json
```

CLI 점수는 키워드 기반 보조 정리다. 알려진 결격·마감·미확인을 사람이 읽을 수 있는 판단으로 덧붙이고, 점수를 합격 확률이나 서류 통과 점수라고 부르지 않는다.

## 마감·정정·충돌 장부

공고마다 `deadline_raw`, 공식 URL, 확인 시각, 원래 시간대, KST(`UTC+09:00`) 표기를 함께 보존한다. 계산·현재 시각 확인은 도구로 한다.

- “상시”·“채용 시 마감”은 고정 미래 날짜로 바꾸지 않는다. 확인한 시점의 상태만 쓴다.
- 날짜만 공개됐다면 시각을 미확인으로 둔다. 23:59:59로 채워 정밀도를 만들지 않는다.
- 접수 마감, 서류 발급 마감, 시험, 면접, 입사일은 서로 다른 일정으로 기록한다.
- 플랫폼과 공식 공고가 다르면 현재 회차의 공식 정정 공고를 우선한다. 둘 다 공식인데 충돌하면 양쪽 문구와 확인 시각을 남기고 사용자 확인 전 낙관적인 마감을 택하지 않는다.
- 온라인 폼의 잠김·조기 마감은 원문 예상 마감과 별도로 보고한다. 근거 없는 재지원·접수 가능성 약속은 하지 않는다.

## JD를 경험 증거로 바꾼다

`실제 업무 과제 → 증명해야 할 행동 → 보유 경험의 출처 → 부족한 부분`을 연결한다. 핵심 역량 몇 개에 집중한다. 공식 사업 사실, 기사 해석, 지원자의 가설을 구분하고 문장별 URL과 시점을 남긴다. 기업 인재상을 반복하거나 알려지지 않은 내부 문제를 단정하지 않는다.

최종 탐색 보고는 **지원 가능 / 확인 필요 / 제외**와 정확한 직무를 먼저 보여준다. 그 뒤 자격 근거·현재 마감·경험 연결·미확인 항목을 적는다. 여러 회사 요청은 실제 요청 목록과 결과 수를 도구로 대조한다.
