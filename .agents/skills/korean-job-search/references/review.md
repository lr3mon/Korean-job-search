# 작성자와 분리한 검토

## 검토 역할과 비용 경계

작성자에게 완성도를 물어보는 대신 검토자는 **틀렸을 수 있는 주장과 누락된 요구**를 찾는다. 독립 검토자를 쓸 때는 현재 초안·문항·JD·근거 장부·금지 규칙만 전달한다. 개인 원본을 다른 모델/서비스에 보내는 행위는 별도 데이터 공개이므로 사용자의 허용 범위와 비용을 확인한다.

별도 유료 에이전트 실행을 자동으로 만들지 않는다. 같은 에이전트가 다시 검토하면 “동일 에이전트 2차 검토”라고 표시한다. 체크리스트 실행은 채용 성과나 실제 독립 모델 평가를 입증하지 않는다.

## 순서를 바꾸지 않는다

1. **문항 계약:** 현재 회차·선택 직무·질문 원문·하위 질문·제한을 대조한다. 문항이나 제한 미확인은 제출용 상태의 차단 사유다.
2. **사실 검토:** 이름·기간·직책·도구·버전·수치·인과 주장을 근거 장부와 한 항목씩 대조한다. 회사 성과가 개인 성과로 변한 지점을 찾는다.
3. **내용 검토:** 질문에 직접 답했는가? 판단의 이유와 실제 행동이 있는가? 결과의 범위와 성찰이 근거를 넘지 않는가? JD의 핵심 업무와 연결되는가?
4. **반례 검토:** 면접관이 “직접 한 부분은?”, “어떤 근거로?”, “다른 요인 때문 아닌가?”라고 물으면 답할 수 있는지 확인한다.
5. **블라인드·개인정보:** 금지 신상과 원치 않는 민감정보가 문서/파일명/속성/링크에 없는지 검사한다.
6. **문체:** 회사명만 바꿔도 통하는 문장, 거창한 포부, 반복 대구, 너무 긴 배경, 반복 수치를 줄인다. 사실을 살리기 위해 필요한 기술 용어·1인칭은 보존한다.
7. **길이와 일치:** 실제 `answers-check`를 모든 답변에 실행하고 검토 문서의 본문·파일·계산값이 같은 버전인지 확인한다. 온라인 값은 별도 승인 없이 변경하지 않는다.

## 검토 출력

[검토 인계서](../templates/review-handoff.md)에 아래 항목을 채운다.

- `차단`: 미확인 필수 자격·현재 문항·제한·사실, 출처 없는 수치, 블라인드 위반, 제한 초과.
- `수정 권고`: 질문을 벗어난 문장, 누락된 판단, 모호한 개인 기여, 근거보다 강한 인과.
- `선택 개선`: 더 간결한 표현, 근거 있는 장면 보강, 경험 배치 조정.
- 각 항목에 `현재 문구 | 이유 | 증거 위치 | 최소 수정안 | 확인자`를 제시한다.

서로 다른 주장을 한꺼번에 점수로 합치지 않는다. 사실 오류는 문체 점수로 상쇄되지 않는다. “합격할 답변”, “합격 확률” 같은 결과 보장을 하지 않는다.

## 수정과 종료

사용자가 승인한 기준 초안을 보존하고 수정본을 별도 파일로 만든다. 수정하지 않기로 한 문항·문단은 도구로 비교해 되돌림이 없음을 확인한다. 수치·이름·기간·책임 범위는 변경 목록으로 검증하고, 길이 검사를 다시 실행한다.

지원자 확인이 필요한 부분은 질문으로 남긴다. 확인되지 않은 내용을 답변에 슬쩍 넣지 않는다. 차단 항목이 남아 있으면 “초안 검토 중”으로 인계한다. 체크가 통과해도 **최종 제출은 수행하지 않는다**. 검토 보고에는 온라인 입력/저장/제출을 하지 않았는지 명시한다.
